# Changelog

## Unreleased

- **Open deck.** The deck from herdr (the mesh, its cells, your library, the rules, this computer, moving a cell; keys 1 to 5) now opens in VS Code too: **Open deck** in the Cells and Meshes title bars, or the command palette. It runs in a terminal in the editor area, with Python 3.10 or newer; a second **Open deck** shows the open one instead of starting another (one deck per window; each deck asks the server about once a minute). The extension brings its own copy of the deck (herdr plugin 0.5.0), checked against its sha256 before it runs. When you start a cell in the deck, a VS Code terminal «a4sx: <name>» opens and runs the start, as a start from the Cells view does. The extension checks each such request itself and runs only `a4sx launch` with `--cell`, `--new-session` or `--a4sx-session`, in a folder inside your home folder that other users can't write to, at most 10 a minute. Each one is a line in Output → a4sx (the time, the name, the folder and the command, then whether its terminal opened). The deck shows anything else (rename, delete, traffic rules, the agent host) as a command to run yourself. The deck's requests go through a folder in the extension's own storage, made for that one deck and removed when its terminal closes. When the extension stops or restarts, its deck terminal closes too.
- **A cell's saves go to one entry, named like the herdr deck's.** **Save its conversation…** on a cell saves to the library entry `<cell>-backup` (title "<cell>: backups"), as the deck's backup does: the first save makes it, every later save is a new version of it. Before, each save of a new conversation made one more `session-<id>` entry. When your library has more than one entry named `<cell>-backup`, you pick the one that gets the new version (newest first). The entry is found by its exact name and saved to by its id, so an entry whose title only contains that name is never used. If the cell has no `<cell>-backup` entry yet and its conversation is already in your library from an earlier save, the save is a new version of that entry and keeps its name and title. No entry is ever renamed.
- **Move a cell from its terminal into the Agents window in one step.** **Open in Agents window** on a cell that runs in a terminal on this computer now offers **Move it into the Agents window**: it stops the cell in its terminal (the CLI waits up to 15 seconds for it to end), waits until this computer's cell list no longer shows it running (at most 20 more seconds; you can cancel), then opens it in the Agents window, where it continues its last conversation (with a4sx CLI 0.59.6 or newer). When the cell list can't be read after the stop, or the cell still runs, it says so and opens nothing. Before, that took three steps: Stop it, confirm, then Open in Agents window again. **Stop it** is still offered.
- **This computer always has two rows**: the agent host's state and the one action that applies (Set up the Agents window, Stop agent host or Start agent host). An unclean end is in the state row's text; the last error is its description, with the whole text in its tooltip. Before, the node gained or lost a row when the host's state changed or an error came or went, so the cells below moved and a click right after a Refresh could land on the wrong cell. When `agent-host status` fails, the second row is **Read it again**; with an a4sx CLI without that command, it is **Update the a4sx CLI**. A fresh last error turns the state row's icon yellow, also while the host runs. While the host runs but the Agents window isn't set up, the action is **Set up the Agents window**; stop such a host with Ctrl+C in its terminal or `a4sx agent-host stop`.
- **Cells and Launch profiles follow the CLI's sign-in.** After `a4sx login` (or a logout) in a terminal, both views read again by themselves. Before, Launch profiles kept saying there was no a4sx sign-in until a Refresh. The extension watches the CLI's sign-in files (`session`, `apikey`) for a change and never opens them.
- **This computer says when the agent host ended because its terminal or VS Code was closed:** "agent host ended when its terminal or VS Code was closed". This needs an a4sx CLI that records that the host's terminal went away (the next CLI release); closing VS Code closes that terminal too. When no reason is recorded (an older CLI, Ctrl+C, a crash), the texts stay as before. The "ended without a clean stop" row is not shown when the reason is known.
- **A cell you start from the Cells view shows as running without a Refresh.** After **Start**, **New cell** or **Start on this computer** opens the cell's terminal, the Cells view reads the cell list again after about 4, 12 and 30 seconds, so the row shows the cell running once its launch has recorded that. This also applies to **Run as cell**, **Convert to a cell** and continuing a saved session in a cell. Before, the row read "stored" until you pressed Refresh.

## 0.9.6

From the from-scratch run on 0.9.4 (a4sx #2309 F4, F5, F12):
- **After the server was busy** (a deploy, a restart), My sessions, Launch profiles and the cells on other machines read again by themselves. They wait as long as the server's Retry-After says, or 5, 10, 20, 40 and then 60 seconds, and the message goes once a read works. Before, "a4sx is busy right now…" stayed until you pressed Refresh.
- **The agent host survives Developer: Reload Window.** The agent host that **Start agent host** or **Set up the Agents window** started ran in a terminal that VS Code ended at every window reload (for example after an extension update), and its cells with it. Its terminal is now kept across a reload, like your own terminals (VS Code's persistent terminal sessions, on by default). After a full restart of VS Code the host still doesn't start by itself.
- **The Agents window's set-up question is a dialog**, not a notification that vanished after a few seconds with the only way forward on it.
- **This computer's last error has its time** ("Last error 11-21 16:00 UTC: …"). An error from before a start that then ran is greyed and reads **Earlier error**. After the agent host ended without a clean stop (a restart of the computer, a kill), the node says so: "agent host ended without a clean stop (e.g. a restart)".
- **The status bar shows the counts from the start.** VS Code reads the cells once, a few seconds after it starts, so the status bar has them before the a4sx view is opened.
- **Restricted Mode.** VS Code doesn't let an extension start a terminal in a window you haven't trusted. Before, **Set up the Agents window** from a notification then did nothing at all. Setting up the Agents window and starting the agent host now say so first and offer **Manage Workspace Trust**; nothing starts until you trust the window.
- **Open in Agents window goes on after the setup.** When the Agents window wasn't set up yet, choosing **Set up the Agents window** in its question now waits until the setup is done and the agent host answers, then opens the cell. There is no second click. A notification shows while it waits, and Cancel stops waiting. If the setup doesn't finish within 30 seconds, a message says so and names the setup's terminal.
- **My sessions after Save its conversation.** My sessions reads your library again a few times while the save runs (after about 8, 20 and 45 seconds), so the new entry or version shows up without a Refresh. With a newer a4sx CLI the save's terminal also ends with one line instead of the server's raw answer.

## 0.9.5

From a from-scratch run on 0.9.4 with the released a4sx CLI 0.59.2 (a4sx #2309 F1, F2):
- **Stop on a cell running in the Agents window.** A failed Stop no longer changes the row. Before, the Cells view read the list again after the failure and showed the cell as stopped while it still ran. a4sx CLI 0.59.12 stops a cell the agent host runs through the host, so VS Code is told. When the CLI or the agent host it started can't do that (the host's status says so), Stop on such a cell asks nothing: it says at once that it needs a4sx 0.59.12 and to close the cell's session in the Agents window, and runs nothing.
- **Stop agent host with an older CLI.** When the CLI or the agent host it started can't be asked to stop (a4sx before 0.59.10; the host's status says so), the row is greyed, without an action, and its tooltip says why and that Ctrl+C in the host's terminal stops it. Before, the button failed with "Update a4sx", which didn't help before a4sx 0.59.10 was released. The checks read what the host can do, not version numbers.

## 0.9.4

- **The browser sign-in pages name VS Code.** Sign in to a4sx tells the server that VS Code started it. With an a4sx server that has #2324, the pages then say to compare the code with the one in VS Code's a4sx sign-in notification and to return to VS Code, not to your terminal. The warning to compare the code is the same as before. Older servers ignore the hint.
- **Allow mesh read works.** The server never puts mesh permissions into one key with others, so the old sign-in asked for a key it refused and the Meshes view said "Meshes are not available on this a4sx server". Allow mesh read now signs in for a key with mesh read alone and keeps it apart; your sign-in stays as it is. The mesh key belongs to your sign-in: signing out, or a sign-in that ended, removes it too, and a new sign-in never uses an earlier one.
- In My sessions listed through the a4sx CLI, a row has no **Resume in Claude Code** (it needs the sign-in here), and the "listed with the a4sx CLI's sign-in" note stays while a filter is set.
- **One sign-in.** When you haven't signed in here but the a4sx CLI on this computer is signed in, My sessions lists your library through the CLI (`a4sx whoami --json`, `a4sx list --json`, CLI 0.59.12 or newer) and says so. It lists only when the CLI is signed in to the same server as this extension, reads it once until you press Refresh, and Refresh and Filter work there too. Saving, publishing and opening a session in Claude Code from VS Code still ask you to sign in here; Resume session and Run as cell use the CLI's sign-in.
- **Convert an Agents-window session to a cell…** with no such session on this computer is the usual case: it now says so in an information notification that starts with the point ("Nothing to convert: no Agents-window session is on this computer, …"), not an error cut after a few words.
- **The cells follow the Agents window.** When a session opens or closes in the Agents window, or the agent host starts or stops, the Cells view reads the cell list again (once per change), so a cell the agent host started no longer reads "stored" until a Refresh.
- **Easier to read at a glance.** In Cells, a row's icon now carries its state as a colour (your theme's own colours): green for a cell running on this computer, blue for one open in the Agents window, yellow for one that waits for an admin or is stored twice; a cell on another machine is green when online and dimmed when offline. When a mesh has more than three cells of other members, they fold into one row, **Other members' cells**, that opens on a click; your own cells on other machines stay listed. The status bar shows **a4sx: 3 cells · 1 running** and opens the Cells view on a click; it shows what the Cells view last read and runs nothing itself.
- **Stop agent host.** While the agent host runs, This computer has **Stop agent host** (also in the Command Palette). It runs `a4sx agent-host stop`, the same stop as Ctrl+C in the host's terminal: the host tells the Agents window first, then ends the cells it started. When cells run in it, it asks first and names them (**Stop it** / Cancel); with none it stops without asking. A notification shows while it waits, and a message says when it has stopped. This needs a4sx CLI 0.59.15 or newer; with an older CLI it says to update, or to stop the host with Ctrl+C in its terminal.
- **Open in Agents window.** A cell stored on this computer now has **Open in Agents window**, first in its menu: it opens the cell's session in VS Code's Agents window (through that window's own link), where the a4sx agent host starts the cell and continues its last conversation. When the agent host isn't running, it starts it (in its terminal **a4sx: agent host**), waits until it answers (at most 30 seconds; Cancel on the notification stops waiting) and then opens the cell: one click. If it doesn't answer by then, a message says so and names that terminal; if it stops with an error before it answers (as `a4sx agent-host status` shows it), the message says so at once, with that error. When the Agents window isn't set up for the agent host yet, it says so and offers **Set up the Agents window**, which now works on the first click. A cell running in a terminal here can't run in the Agents window too: it says so and offers **Stop it**. Start in terminal stays as it is.
- **`--mesh` only when it's needed.** A start from Run as cell in terminal, Convert into an existing cell and Start from a saved session added `--mesh <id>` to `a4sx launch --cell` even when no other cell of that name is stored here. It is added now only when another stored cell has the same name (compared by its id, not as the same object of a list read again).
- **More on a cell's row.** A cell on another machine has **Last messages** (what happened to the last messages between your cells on this computer and that cell, from this computer's own records: `a4sx mesh deliveries`) and **Why can or can't I message it** (the rule that decides, from `a4sx mesh policy --explain`). A cell stored on this computer has **Save its conversation…** and, while it isn't running, **Start from a saved session…**. Save uploads the cell's last conversation with `a4sx push` in a terminal and asks first; the saved copy is scrubbed (secrets removed; e-mail addresses, host names, IP addresses and your home folder in paths replaced), and the confirmation says so. A later save of the same conversation becomes a new version of its library entry. Start from a saved session lists your library and then runs as Run as cell in terminal does, with this cell chosen. Nothing here runs by itself: each action asks the a4sx CLI once, when you choose it. There is no hand-off between computers yet: a scrubbed copy is not an exact copy.
- **This computer.** Above the meshes, Cells now shows the agent host on this computer, from `a4sx agent-host status --json`: whether it runs and at which address, **Set up the Agents window** when VS Code isn't set up for it (`a4sx agent-host setup-vscode` in a terminal, which also starts the agent host there), **Start agent host** when it is set up but doesn't run (it runs in a terminal until you stop it), and its last error. A cell open in the Agents window is marked **open in the Agents window**, first on its row and in its tooltip. While the Cells view is visible and VS Code has focus, the status is read again every 30 seconds (a local `a4sx agent-host status`, no server call) and when the window gets focus, so a host stopped in its terminal shows as stopped. An a4sx CLI without that command gets one line that says so; any other failure shows the CLI's own line. After **Start agent host** or **Set up the Agents window**, the node reads the status again a few times, so it shows the host running without a Refresh. On Windows the host is started as the Python of your a4sx command, so Ctrl+C stops it without "Terminate batch job (Y/N)?". The last error's row is short; its tooltip has the whole text.
- Shorter, plainer words: a cell the signed-in account doesn't list reads **other account** (the row was cut at the default width), and its tooltip says "another account", which can be a colleague's. The tooltip's path line reads **Connection path: …** and is left out when there is none. The mesh's traffic preset is no longer on the cell's row (it was cut at the default width); the tooltip says **traffic: Open** (Own cells, Closed), and the mesh's row still shows it.
- **Start one of your own cells here.** A cell of yours that runs, or ran, on another computer ("yours, on another machine") now has **Start on this computer**, inline and in its menu. It asks for a folder, as New cell does, and runs `a4sx launch --cell NAME --mesh MESH` in a terminal. The a4sx CLI decides: while the cell still runs on the other computer it starts nothing and says how to stop it there; otherwise it moves the cell here. This needs a4sx CLI 0.55 or newer and a sign-in in the CLI. Other people's cells still have no actions.
- **A cell of another account no longer reads "registry revoked".** Signed in to one account, with cells of another, the Cells view called working cells revoked. With a4sx CLI 0.59.7 such a cell reads **other account**. With an older CLI it still reads **registry revoked**, and its tooltip now says that a cell that still starts belongs to another account, rather than suggesting you remove it.
- **Cells comes first.** The a4sx side bar now starts with Cells and Meshes. My sessions and Marketplace start collapsed; Launch profiles stays open. This applies to a fresh install, because VS Code keeps the layout you already have.

## 0.9.3

- **Start in terminal**, **New cell**, **Run as cell in terminal** and the **Convert** actions no longer add `--mesh-reduced-isolation`, and the extension no longer asks its own reduced-isolation question before them. That flag accepts reduced isolation for one start only and stores nothing, so a cell started from here never had your answer stored. A later start of that cell without a terminal, for example the agent host's, was then refused ("nobody has accepted that for this cell on this computer yet"). Now the a4sx CLI asks its own question in the terminal, once per cell and per computer, and stores your answer. The text is the CLI's.
- This needs a4sx CLI 0.32.0 or newer. With an older CLI, these actions say so and offer **Update a4sx CLI**; nothing starts.
- Because of that, a cell never starts in such a folder from here. A conversation the CLI recorded in your home folder (0.9.1 started cells there when no folder was open) can't be continued in a cell. A dialog says why and offers **Choose a folder…**, where the cell starts a new conversation; **Continue in home folder** is gone. **New cell** and **Run as cell** with no folder open ask for one instead of using the home folder. A folder chosen there, or a session that ran in such a folder, is refused with the reason before anything starts.
- **Copy launch command** copies `a4sx launch --cell <name>` without the flag too.
- The **Keep my sign-in (reduced isolation)** option of Run as cell and Convert is gone, and so is the warning for a session that is only in your library. The CLI's yes keeps your sign-ins in the cell, as that flag did, and on a computer where the sandbox works the flag never changed the isolation. One thing the flag did that the yes doesn't: without it, the CLI doesn't start a cell in a folder that holds your Claude Code folder or the a4sx folders, such as your home folder. The one option left is **Deliver messages from mesh peers without asking**.

## 0.9.2

- **Start in terminal** in the Cells view continues the cell's last conversation. Before, it started a new one. The a4sx CLI records each cell's last conversation and its folder on this computer (since CLI 0.31.10). Start now runs in that folder and adds `-- --resume <session id>` to `a4sx launch --cell <name>`, while the conversation's transcript is on this computer. A notification names the conversation and its folder; for a new conversation, type `/clear` in it. If the transcript is gone, the cell starts a new conversation in that folder, and the notification says why. `a4sx mesh cells --json` doesn't name the conversation, so the extension reads the CLI's record (`cell-last-session.json` in the cell's a4sx state folder: a session id and a folder, nothing secret). This works with CLI 0.40.3.
- Start runs in the cell's own folder. Before, it ran in the window's folder, or your home folder when no folder was open, and Claude Code only finds a conversation from the folder it ran in. When no conversation is recorded, or its folder is gone, you choose the folder in a dialog. It opens on the folder you last started the cell in, else on the folder of the last prompt typed in the cell. It never starts in your home folder without asking. That includes a conversation the CLI recorded in your home folder: 0.9.1 started cells there when no folder was open. For such a conversation, a dialog offers **Continue in home folder** or **Choose a folder…**. In a folder you choose, the cell starts a new conversation.
- The Claude Code extension's `claude` is found again after Claude Code updates. VS Code installs an update into a new folder (`anthropic.claude-code-<version>-<platform>`) and removes the old one, so an `A4SX_CLAUDE` path to the old folder pointed at nothing. The path is now looked up at every start, in the newest installed version, skipping folders VS Code has marked for removal. The known layout (`resources/native-binary/claude.exe`, checked in 2.1.325 and 2.1.329 for win32-x64) comes first, then a short search of the extension's folder. If none has a `claude`, no `A4SX_CLAUDE` is set and the CLI finds `claude` on PATH. If it isn't there either, one message names the install command, with **Copy install command** and **Start anyway** (for a `claude` you set with `a4sx config set harness.claude_path`; after that, the message isn't shown again on this computer). Only builds for this platform count, this machine's architecture first. On macOS and Linux, only a `claude` you may run counts.
- If your own `A4SX_CLAUDE` names no program, the extension says so before anything starts, with the fix. It offers **Use Claude Code's claude** for this start.
- A cell's terminal isn't revived when VS Code restarts. A revived terminal kept the environment and folder of its first start, including an `A4SX_CLAUDE` that a Claude Code update had since removed. After a restart, start the cell again from the Cells view.

## 0.9.1

- **Convert to cell…** is now one flow. In the normal case it no longer asks which session a tab shows and shows no confirm dialog. The mesh list comes first and names the session that will be converted: its title and the start of its session id in the list's title, its folder and when it last changed in the placeholder. The last row, **Not this session? Choose another…**, opens the session list. The mesh list shows your active meshes with your role and their member count, plus **Choose the mesh in the browser**. When you aren't signed in, or your meshes can't be read, it says so and still offers those two rows. Then you name the cell. The box is prefilled with the session title's first words as a cell name; leave it empty and the a4sx server proposes two random words. The suggestion comes from the session title only, never from the computer's name. The command adds `--as <name>` and `--mesh <mesh id>` to `a4sx launch --new-cell`. The browser approval still shows both, and you can change them there.
- **Convert to cell in mesh…** is gone from the menus: its mesh list is now part of **Convert to cell…**. Its command id still works, for keybindings. **Convert into a cell…** is now called **Convert into an existing cell…**. Its cell list names the session in its title instead of a separate confirm dialog.
- Why the session list appeared: the tab's label is Claude Code's summary of the session, not always the title the transcript ends with. Before a session has a title, the label is its prompt. A tab also keeps the first title Claude Code generated for it, while the transcript can end with a newer one. And a session's copies in other folders (a cell's folder, for example) share its title. Each of those matched no session or several, so you were asked. Now a label also matches a title the session had before, and the prompt of a session with no title yet. When several sessions match, two kinds drop out: first, when some matches are in this window's folders (or their `.claude/worktrees`), the matches outside them; then a session that another open Claude Code tab alone matches by its current title. When these rules leave none, you are asked. The extension also reads the newer transcripts of this window's folders, not only the newest 80 on the computer, so a tab that has been idle a while is still found. When several sessions fit equally, or the tab is still labelled "Claude Code", you are still asked, never guessed for. The list then shows the matches first, then this window's sessions, then the other sessions of Claude Code for VS Code.
- Why the meshes aren't a submenu: VS Code builds context menus from the extension's manifest, so their entries and titles are fixed. An extension can only show or hide them, so a submenu can't list your meshes by name.
- **Save session to a4sx** finds the tab's session the same new way. It still asks you to confirm a session it found without asking you.

## 0.9.0

- New command **a4sx: Convert an Agents-window session to a cell…** in the Command Palette. It lists this computer's Claude sessions that were started through the Claude Agent SDK, newest first, by title (or first prompt), folder, when they last changed and the start of their session id. You pick one and confirm it in a dialog with the same details as for **Convert to cell**, with **Choose another…** and Cancel. Then you choose the cell, as in **Run as cell in terminal**: a cell you already have (`a4sx launch --cell <cell> [options] -- --resume <session id>`) or **New cell…** (`a4sx launch --new-cell [options] -- --resume <session id>`). The terminal runs in the folder the session ran in.
- Why the Command Palette and not a menu on the session: VS Code's Agents window offers extensions its session menus only as proposed API, which a Marketplace extension can't use.
- How the sessions are found: the Agents window runs Claude through VS Code's agent host, which uses the Claude Agent SDK, and the SDK saves each session where Claude Code saves its sessions (`projects/<folder>/<session id>.jsonl` in the Claude Code folder: `CLAUDE_CONFIG_DIR`, or `~/.claude`), with its records marked as SDK sessions. The list shows the sessions with that mark. Other programs built on the Claude Agent SDK for TypeScript use the same mark, so their sessions can show up too; the confirm dialog is there so you pick the one you mean. Sessions of a remote agent host are on that machine and aren't listed.
- The session id comes from the transcript's file name and is checked again right before the start. From a transcript only its first records (to see that it is an SDK session, its folder and its first prompt) and its title records are read; they are only shown to you and never reach the command line.
- The session isn't moved out of the Agents window: the cell continues it in a terminal. The confirm dialog and the message after the start say to archive or close it in the Agents window, so that two programs don't write the same session.
- New action **Convert into a cell…** in the context menu of a Claude Code tab, and in the Command Palette while such a tab is active. It works like **Convert to cell**, but you then choose the cell as in **Run as cell in terminal**: a cell you already have, or **New cell…**.

## 0.8.0

- New actions **Convert to cell** and **Convert to cell in mesh…** in the context menu of a Claude Code tab (right-click the tab), and in the Command Palette while such a tab is active. They run the tab's session in a new cell: a terminal runs `a4sx launch --new-cell [options] -- --resume <session id>` in the folder the session ran in. The options are the two of **Run as cell in terminal** (**Keep my sign-in (reduced isolation)**, **Deliver messages from mesh peers without asking**), and the reduced-isolation dialog is shown as for every cell. You approve the new cell in your browser, where you pick its mesh.
- **Convert to cell in mesh…** first lists your active meshes and adds `--mesh <mesh id>` to the command. The browser approval still asks for the mesh; if you pick another one there, the a4sx CLI says so before it starts the cell. It is offered when you are signed in and your a4sx server has meshes.
- The Claude Code extension doesn't tell other extensions which session a tab shows. The tab is matched by its title, which Claude Code writes into the session's transcript on this computer. When exactly one session has that title, **Save session to a4sx** and **Convert to cell** first ask you to confirm it. The dialog shows its title, when it last changed, its first prompt (shortened) and the start of its session id, with **Choose another…** and Cancel. If no session or more than one has that title (a new chat, or two sessions with the same title), nothing is matched automatically: the extension lists this computer's newest sessions with the same details and you choose. **Preview save to a4sx (dry run)** skips the confirm, and its terminal names the session (as does the save's). From a transcript only its title records and its first prompt are read. They are only shown to you, in the dialog, the pick and the terminal's banner. The extension never logs them, stores them or puts them on a command line; VS Code may keep the banner with the terminal's scrollback.
- The tab isn't turned into a cell in place: the session continues in the terminal. The extension then offers **Close tab**, so the session isn't used in two places.
- New actions **Save session to a4sx** and **Preview save to a4sx (dry run)** in the same context menu. They save the session of that tab, found as above: a terminal runs `a4sx push <transcript>`. **Save this session** still saves the most recently changed session on this computer (`a4sx push --latest`), which need not be the tab you are looking at.
- If your library already holds that session, the save becomes a new version of its entry (`--into <entry>`). If it holds it more than once, you choose the entry. When the extension can't read your library (signed out in the sidebar, an expired sign-in, or offline), it saves nothing and says why and what to do: a plain push could add the session as a second entry instead of a new version. If the entry's id is one the a4sx CLI doesn't take, it says so and offers **Save as a new entry**.
- **Preview save to a4sx (dry run)** runs `a4sx push <transcript> --dry-run`: the CLI lists what its scrub would change and uploads nothing. It needs no sign-in.
- The menu entries appear when you right-click a Claude Code tab, whichever editor is active. They are tied to the clicked tab's resource (`webview-panel:…/webview-claudeVSCodePanel-…`). VS Code before 1.106 names no view type there, so on those versions they appear on webview tabs while a Claude Code tab is the active editor.
- A right-click doesn't make the tab's editor group active, and VS Code tells extensions only the clicked tab's position in its group. With split editors, when more than one group could hold the clicked tab, the extension asks which Claude Code tab you mean (by title and editor group) instead of guessing. If the clicked tab isn't a Claude Code tab, it says so and does nothing.
- When a session can't be resumed on this computer (its folder is gone, or its transcript names no folder Claude Code files it under), **Convert to cell** says so and names the next step: save it to a4sx, then **Run as cell in terminal** on it in **My sessions**.

## 0.7.0

- **Cells** shows each cell's tags and one line about its mesh's policy, from `a4sx mesh cells --json` (a4sx CLI 0.28.0 or newer): "Open · can talk to 3", "Own cells · can talk to 1" or "Closed · can talk to 0", or the policy alone ("Open") when the number of cells it can talk to isn't known. ## 0.4.0

- New view **Cells**: the mesh cells the a4sx CLI has stored on this computer, with their mesh, the default cell, and whether a mesh admin still has to approve them. The list comes from `a4sx mesh cells --json`. The extension never reads the cells' keys.
- **Start in terminal** on a cell runs `a4sx launch --cell <name> --mesh-reduced-isolation` in a new terminal in your workspace folder. **New cell** runs `a4sx launch --new-cell --mesh-reduced-isolation`, which has you approve the cell in your browser. The first start on a computer explains reduced isolation in a dialog, and starts only if you accept. The answer is remembered for that computer.
- **Set as default**, **Forget on this computer** (after you confirm) and **Open in browser** on each cell.
- If the Claude Code extension is installed, cells use the `claude` that comes with it (passed to the CLI as `A4SX_CLAUDE`).
- **Install a4sx CLI**: when the a4sx CLI isn't found, the extension installs it itself. It finds Python 3.10 or newer (on Windows, it offers `winget install Python.Python.3.12` if there is none), downloads the CLI from the a4sx server, checks each file's SHA-256 checksum, and saves it in its own storage with a small launcher. It needs no admin rights and no `PATH` change. It updates that copy once a day in the background. **Update a4sx CLI** updates it in a terminal.
- **Install a4sx** (offered once when you resume without the CLI) and the "a4sx command was not found" message now use this install instead of an installer command.

- New view **Meshes**: your a4sx meshes and your cells in each one, with their status, presence, reach and last seen, grouped by machine when they run on more than one. The cells are read when the view is shown or a mesh is expanded, then every 30 seconds while it is visible; a busy server is asked less often. The view appears only when your a4sx server has meshes. If the server doesn't list cells yet, the view shows your meshes alone.
- **Start session in mesh** runs `a4sx launch --ipc-proxy --mesh <id> --as <name>` in a new terminal, with a name you type, in an active mesh you're a member of. It first runs the CLI's isolation check: a host that isn't ready is refused with the CLI's reason and the commands that fix it, and reduced isolation needs an explicit click for that start.
- Creating a mesh, redeeming an invite and opening a mesh's page open the website.
- The view needs the new permission `mesh:read`. **Allow mesh read** asks for it with a new browser sign-in. Sign-in itself doesn't ask for it.
